# 输出完整性修复

> 历史验证记录。2026-09-20 发布前安全修复已将外部 MCP 改为默认关闭；当前行为以 README 和 SECURITY.md 为准。

本次修改修复了最终消息尾部丢失、异常 EOF 被当作成功、interrupted 状态被当作成功，以及停止时未保存最后一次缓冲更新的问题。

- 以最终 item/completed 校正回答与推理摘要；分开保存过程消息和最终答案。
- 服务端发送完整结果快照与状态。前端必须同时收到完成状态、完整快照和结束标记，才认定成功。
- 中断或失败保留已收到的正文与推理，明确标记未完成；每个答案版本保存模型、推理档位、用量和上下文压缩记录。
- 自动推理档位选择模型目录中的最高可用档，手动选择优先；界面显示实际档位。推理摘要请求为 detailed，摘要不是模型全部内部推理。
- 只读模式保持文件与命令限制；项目模式开放项目内命令、图片查看与运行工具；完全访问模式恢复运行时支持的浏览器、图片生成、技能、插件等能力。多代理功能已启用，以匹配 ultra 档。
- MCP 服务能力默认开放，用户关闭 MCP 的选择仍被尊重。账号凭据交换、应用外自动化、跨会话记忆不自动开启。
- 审批和补充输入通过页面对话框往返传递。未实现的运行时协议仍明确拒绝，不伪造工具结果。
- PDF 完整模式传递所有已有页图和文字，新 PDF 不再按页数自动退为文字模式；页面尚未准备好时在生成入口给出明确错误。用户已选择的仅文字模式保留。
- 网页材料不再按 12,000/15,000/30,000 字符静默截短，不再只取前两个 URL。获取失败会明确标识未读取，供模型继续检索。
- 传输保留明确报错的资源上限：单图 12 MB、总图像 256 MB、最多 1,500 张图片、网页 8 MB。超过限制报错，不伪装为完整材料；模型服务自身仍有上下文和输入限制。
- 源码依赖与桌面运行时统一为 Codex SDK/CLI 0.154.0。

验证：85 项回归测试通过；TypeScript 和修改文件的 ESLint 检查通过；正式前端构建通过；输入及审批对话框经过独立浏览器验证。一次真实 Astra/ultra 调用正常结束，最终快照和返回正文一致。

该次真实调用只验证模型配置和文本传输，并未逐一实际执行全部浏览器、插件或多代理工作流。恢复工具配置不代表所有插件均已安装或账号均已连接。

应用升级不会自动补回历史回答中已经丢失的内容。需要补回时，应按已保存的线程/回合记录重新导入，或重新生成。
